# Project Rules

이 파일은 Antigravity 에이전트가 본 프로젝트에서 준수해야 하는 행동 지침 및 코딩 규칙입니다.

---

## 1. 코딩 지침 (Behavioral Guidelines)

* **1. 코딩 전에 생각하기**: 함부로 짐작하지 말고, 불확실한 점이 있다면 즉시 멈추고 사용자에게 질문하십시오. 여러 해석이 가능할 경우 대안을 제시하여 확인을 받으십시오.
* **2. 단순성 우선**: 문제를 해결하는 최소한의 코드만 작성하며, 예측에 의한 미리 설계나 불필요한 추상화 레이어를 만들지 마십시오.
* **3. 정밀하고 국소적인 변경 (수술적 변경)**: 수정이 필요한 부분만 정확히 편집하고, 무관한 주변 코드나 포맷을 건드리지 마십시오. 단, 본인의 작업으로 인해 미사용 상태가 된 코드(import, 변수, 함수 등)는 말끔히 정리하십시오.
* **4. 목표 지향적 실행**: 작업을 시작하기 전 명확한 성공 기준을 정의하고 검증될 때까지 반복 확인하십시오. 다단계 작업 시 간단한 실행 단계를 수립하십시오.
* **5. 한국어 문맥에서 종결자 콜론(:) 생략**: 한국어 문장 끝에는 영어 관습인 콜론 `:` 대신 마침표(`.`), 물음표(`?`), 느낌표(`!`)를 종결자로 사용하십시오. (예외: 소스코드 내부, 키-값 쌍, 단순 라벨)
* **6. 소스 파일 상단에 한글 주석 한 줄 작성**: 새로 생성하는 모든 소스 파일의 첫 번째 줄(필수 지시문 아래)에는 해당 파일의 역할을 요약한 한글 주석 한 줄을 명시하십시오. (설정 파일 제외)
* **7. 계획 + 체크리스트 + 컨텍스트 노트 작성**: 규모가 큰 작업을 수행하기 전에 반드시 계획(Plan), 태스크 체크리스트(`task.md`), 그리고 컨텍스트 노트를 아티팩트로 준비하고 진행 사항을 기록하십시오.
* **8. 완료 선언 전 테스트 실행**: 코드를 수정한 후 완료를 보고하기 전에 반드시 테스트 명령어(`npm test` 등)를 구동하거나, 테스트가 없는 경우 빌드/컴파일 오류가 없는지 확실히 확인하십시오.
* **9. 의미 있는 단위로 커밋 (Semantic Commits)**: 논리적 변경 단위 하나가 완료될 때마다 의미 있는 단위로 즉시 커밋을 수행하십시오.
* **10. 에러를 짐작하지 말고 직접 읽기**: 에러가 발생하면 짐작으로 패치하지 말고, 실제 찍힌 오류 메시지와 스택 트레이스 전체를 직접 확인하여 해결하십시오.
