# 롤링 Walk-Forward 컨텍스트 노트

## 목적
앞선 단일 분할(상반기→하반기)은 검증 구간이 3주로 짧아 "기간이 짧아서 ROI가 낮다"는
반론을 배제하지 못했다. 이를 완전히 제거하기 위해.
- 학습(train)·검증(test) 창을 **동일 길이(8주)**로 맞춘다 → 기간 편향 제거.
- 데이터 전체(2025-01~2026-07)를 8주 단위로 굴려 **여러 fold**를 만든다 → 표본 확대.
- 모든 성과를 **주당 기하수익률**로 정규화해 창 길이와 무관하게 비교한다.

## 방법
- fold k: train=[t, t+8주] 최적화 → 그 파라미터 고정 → test=[t+8주, t+16주] 적용.
  step=8주(검증창 비중첩). 정석 walk-forward.
- 최적화 대상은 targetRoi·slRoi (사용자 그리드와 동일 성격). 3×3 그리드로 축소해
  실행시간을 관리(전체 성능 데모엔 충분, 오히려 과적합을 과소평가하는 보수적 방향).
- 나머지 config(entryMode·penetration·waits)와 EXIT_SLIPPAGE_RATE=0.0005는 실전과 동일 고정.
- 비교 기준선: 현재 실전 파라미터(0.05/0.14)를 동일 test 창에 적용.

## 판정 로직
- opt IS주당 ≫ opt OOS주당 이 여러 fold에서 반복 → 과최적화(파라미터가 일반화 안 됨).
- opt OOS주당 ≤ fixed OOS주당 → 매 fold 최적화가 고정 파라미터보다 못함 = 최적화 무의미.
- 정규화·다중 fold이므로 "기간 짧음/운" 반론이 성립하지 않는다.

## 한계
- 8주 검증창 ≈ 60~70건. 여전히 완벽하진 않으나 단일 3주보다 훨씬 견고.
- 2024 하반기 워밍업은 캐시 없으면 API로 페치(첫 실행만 느림).
